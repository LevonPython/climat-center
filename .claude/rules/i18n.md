# Translations

For adding, renaming or removing strings use the `i18n-sync` skill. Check with `node .claude/scripts/check-locale-parity.js`.

## Two separate catalogues
- Client: `client/public/locales/{hy,en,ru}/common.json`, bundled through `resources` in `client/next-i18next.config.js`, which `serverSideTranslations` reads. A new namespace must be added there. Pages render from the text in their own props, through `client/components/site/PageTranslations.tsx`.
- Admin: `admin/public/locales/{hy,en,ru}/common.json`, loaded over HTTP by `admin/src/i18n.ts`.
- Admin form labels: `admin/public/locales/{hy,en,ru}/schema.json`, keyed by the exact English label from the server schemas. `admin/__tests__/schemaLabels.test.ts` checks them.

## Content
- Every key exists in all three locales. `hy` is the default, so write real Armenian, never an English or Russian placeholder.
- Use `{{name}}` interpolation. Don't build sentences by concatenating translations, because word order differs by language.
- Plurals: Russian needs `_one`, `_few`, `_many`, `_other`.
- Armenian strings tend to run long, so check layouts at phone width.

## Language codes
Armenian is `hy` everywhere: routes, files, DB suffixes and the `lang` attribute. Never use `am`, which means Amharic.

## DB content is separate
Multilingual DB fields use `*_ru`, `*_en`, `*_hy` columns or JSON keys, edited in the admin. They aren't in these catalogues, and `t()` is their fallback when a value is missing.
