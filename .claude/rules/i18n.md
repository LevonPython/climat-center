# Translations

For adding, renaming or removing strings use the `i18n-sync` skill. Check with `node .claude/scripts/check-locale-parity.js`.

## Two separate catalogues
- Client: `client/public/locales/{am,en,ru}/common.json`, bundled through `resources` in `client/next-i18next.config.js`. A new namespace must be added there.
- Admin: `admin/public/locales/{am,en,ru}/common.json`, loaded over HTTP by `admin/src/i18n.ts`.

## Content
- Every key exists in all three locales. `am` is the default, so write real Armenian, never an English or Russian placeholder.
- Use `{{name}}` interpolation. Don't build sentences by concatenating translations, because word order differs by language.
- Plurals: Russian needs `_one`, `_few`, `_many`, `_other`.
- Armenian strings tend to run long, so check layouts at phone width.

## `am` is not a standard language code
`am` is this project's name for Armenian, but in BCP-47 it means Amharic. Armenian is `hy`. Keep `am` in routes, files and DB suffixes, and map it to `hy` wherever the code is read by something external: `Intl`, `toLocaleString`, the `lang` attribute, hreflang.

## DB content is separate
Multilingual DB fields use `*_ru`, `*_en`, `*_am` columns or JSON keys, edited in the admin. They aren't in these catalogues, and `t()` is their fallback when a value is missing.
